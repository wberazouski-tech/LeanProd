# Catalog items

`CatalogItem` — агульны даведнік таго, што арганізацыя вырабляе, выкарыстоўвае, набывае або ўлічвае. У базе выкарыстоўваецца адна табліца `CatalogItems`, а ў Angular кожны тып адкрываецца на асобнай старонцы.

## Тыпы

Пералік зададзены жорсткім enum `CatalogItemType`: `Product`, `Work`, `PrimaryMaterial`, `AuxiliaryMaterial`, `SemiFinishedProduct`, `Packaging`, `ToolingAndTools`, `SparePart`, `PurchasedService`, `Waste`.

`ByProduct` асобна не вылучаецца: пабочная прадукцыя ўлічваецца як `Product`.

## Палі і правілы

- `Id` — тэхнічны GUID, генеруецца аўтаматычна і не паказваецца карыстальніку;
- `WorkingName` — абавязковая працоўная назва;
- `FullName` — неабавязковая поўная назва; калі яна пустая, у дакументах трэба выкарыстоўваць працоўную назву;
- `ArticleNumber` — неабавязковы артыкул, нармалізуецца праз `Trim` і верхні рэгістр;
- `Type` — абавязковы тып з enum;
- `CatalogItemClassId` — абавязковая спасылка на клас элемента таго ж `Type`;
- `BaseUnitOfMeasureId` — абавязковая актыўная базавая адзінка вымярэння;
- `Description` — неабавязковае апісанне;
- `IsActive`, audit-палі і `RowVersion`.

Запоўнены артыкул унікальны ў межах тыпу. Гэта забяспечана праверкай сэрвісу і filtered unique index `(Type, ArticleNumber) WHERE ArticleNumber IS NOT NULL`. Таму адзін артыкул можа паўтарацца ў розных тыпах, а пустых артыкулаў можа быць некалькі.

## API і доступ

`GET /api/catalog-items` абавязкова атрымлівае `type` і падтрымлівае пошук і фільтр актыўнасці. Стварэнне, рэдагаванне, актывацыя і дэактывацыя выконваюцца праз той жа controller. Прагляд патрабуе `MasterData.View`, змяненне — `MasterData.Manage`.

Для хуткай змены класа элемента выкарыстоўваецца:

```http
PATCH /api/catalog-items/{id}/class
```

Body:

```json
{ "catalogItemClassId": "..." }
```

Endpoint правярае, што клас існуе, актыўны, не з'яўляецца групай і належыць да таго ж `CatalogItemType`, што і сам item.

## Classes

`CatalogItemClass` — іерархічны класіфікатар унутры канкрэтнага `CatalogItemType`. Кожны тып мае сваё асобнае дрэва classes.

Табліца `CatalogItemClasses`:

- `Id` — тэхнічны GUID;
- `Type` — тып каталожнага элемента;
- `Code` — код, унікальны ў межах `Type`;
- `Name` — назва;
- `IsGroup` — група або канчатковы клас;
- `ParentId` — бацькоўскі вузел;
- `IsActive`;
- audit-палі і `RowVersion`.

Правілы:

- `ParentId` можа спасылацца толькі на `CatalogItemClasses`, дзе `IsGroup = true`;
- parent павінен быць таго ж `Type`;
- item можа быць прывязаны толькі да актыўнага class, дзе `IsGroup = false`;
- group нельга дэактываваць, калі пад ёй ёсць актыўныя падгрупы/classes або актыўныя items;
- нельга змяніць `IsGroup`, калі ў вузла ўжо ёсць children або items;
- цыклы ў дрэве забаронены.

API для classes:

- `GET /api/catalog-item-classes?type=...`
- `GET /api/catalog-item-classes/options?type=...&activeOnly=true`
- `GET /api/catalog-item-classes/{id}`
- `POST /api/catalog-item-classes`
- `PUT /api/catalog-item-classes/{id}`
- `POST /api/catalog-item-classes/{id}/activate`
- `POST /api/catalog-item-classes/{id}/deactivate`

## Кошт і гісторыя змяненняў

Актуальны кошт паказваецца ў спісах каталога і рэдагуецца ў форме элемента. Кошт
захоўваецца як `decimal(18,2)`, мае не больш за два знакі пасля коскі і не можа быць адмоўным. Кожная фактычная змена
стварае новы радок у `CatalogItemCostHistory` з часам `EffectiveFromUtc`; папярэднія
радкі не перазапісваюцца і не выдаляюцца. Стварэнне элемента таксама стварае
пачатковы запіс гісторыі. Валюта вызначаецца наладай арганізацыі
`DefaultCurrencyCode`.

Міграцыя `AddCatalogItemCostHistory` дадае табліцу, знешні ключ без каскаднага
выдалення, праверку неадмоўнай сумы і індэкс `(CatalogItemId, EffectiveFromUtc)`.
Для існуючых элементаў яна бяспечна стварае пачатковы запіс з коштам `0`.

## Інтэрфейс

Кожны тып мае ўласны маршрут і пункт асноўнага меню. Старонкі выкарыстоўваюць адзін reusable `CatalogItemsComponent`: у URL і route data змяняецца тып, але табліца, дыялогі і правілы захавання не дублююцца. Форма стварэння і рэдагавання адкрываецца ў асобным дыялогу; рэдагаванне запускаецца кнопкай-алоўкам у радку.

Старонка каталога арганізавана як двухпанэльны інтэрфейс:

- злева табліца `Items`;
- справа дрэва `CatalogItemClasses`;
- выбар root-class без parent паказвае ўсе items бягучага тыпу;
- выбар group паказвае items усіх падпарадкаваных канчатковых classes;
- выбар канкрэтнага class паказвае толькі items гэтага class;
- кнопкі `Add group` і `Add class` знаходзяцца ў правай панэлі;
- кнопка `Add item` знаходзіцца ў левай панэлі і пры выбраным class аўтаматычна падстаўляе гэты class у форму.

Табліца items падтрымлівае сартыроўку па асноўных калонках і змяненне шырыні калонак мышшу праз правы край загалоўка. Шырыня ўсёй табліцы лічыцца як сума шырынь калонак, таму пры resize суседнія калонкі не павінны перакрываць адна адну; калі табліца не змяшчаецца, выкарыстоўваецца гарызантальны scroll.

Items можна перацягваць мышшу з табліцы на class у правай панэлі. Drop дазволены толькі на актыўны канчатковы class, не на group. Пасля пераносу frontend выклікае `PATCH /api/catalog-items/{id}/class` і абнаўляе радок у табліцы.
