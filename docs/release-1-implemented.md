# Release 1 — рэалізаваныя магчымасці

Актуальна на 21 жніўня 2026 года. Дакумент апісвае фактычна рэалізаваную частку Release 1, а не ўвесь запланаваны аб’ём рэлізу.

## 1. Карыстальнікі і доступ

Рэалізавана адміністрацыйнае кіраванне карыстальнікамі:

- прагляд, пошук, фільтрацыя і пагінацыя;
- стварэнне і рэдагаванне карыстальніка;
- прызначэнне адной або некалькіх роляў;
- актывацыя і дэактывацыя;
- скід пароля з адкліканнем refresh-токенаў;
- запіс часу апошняга ўваходу;
- optimistic concurrency праз `ConcurrencyStamp`;
- security audit адміністрацыйных аперацый;
- забарона дэактывацыі ўласнага акаўнта;
- забарона выдалення ролі ў апошняга актыўнага `SystemAdministrator`.

Дзейнічаюць ролі:

- `SystemAdministrator`;
- `MasterDataAdministrator`;
- `EquipmentOperator`;
- `QualityRegistrar`;
- `ShiftReportEditor`;
- `Viewer`.

Доступ да даведнікаў кантралюецца permissions `MasterData.View` і `MasterData.Manage`. Праверкі ў Angular выкарыстоўваюцца толькі для навігацыі; канчатковае рашэнне заўсёды прымае API.

Асноўныя endpoints:

```text
GET    /api/users
GET    /api/users/{id}
POST   /api/users
PUT    /api/users/{id}
PUT    /api/users/{id}/roles
POST   /api/users/{id}/activate
POST   /api/users/{id}/deactivate
POST   /api/users/{id}/reset-password
GET    /api/roles
```

## 2. Налады карыстальніка

Для кожнага карыстальніка можна незалежна задаць:

- мову інтэрфейсу;
- падраздзяленне па змаўчанні;
- месца захоўвання па змаўчанні.

Падраздзяленне і месца захоўвання не звязаныя паміж сабой у профілі карыстальніка. Можна выбраць любое актыўнае падраздзяленне, любое актыўнае месца, толькі адно з іх або не выбіраць нічога.

Гэтыя значэнні вяртаюцца ў адказах `login`, `refresh`, `/api/identity/me` і адміністрацыйных API карыстальнікаў.

## 3. Лакалізацыя

Angular падтрымлівае runtime-пераключэнне мовы праз Transloco:

- `be` — беларуская;
- `en` — англійская.

Пераклады знаходзяцца ў:

```text
lean-prod-web/src/assets/i18n/be.json
lean-prod-web/src/assets/i18n/en.json
```

Пасля ўваходу выкарыстоўваецца `PreferredLanguage` з профілю. Да ўваходу выбар захоўваецца ў `localStorage`. Новая мова прымяняецца без асобнай зборкі Angular.

Endpoint асабістай налады:

```text
PUT /api/identity/preferences
```

## 4. Падраздзяленні

Рэалізаваны іерархічны даведнік `Department`.

Палі:

- аўтаматычны ўнутраны `Id` тыпу GUID;
- бізнес-код `Code`;
- назва;
- апісанне;
- бацькоўскае падраздзяленне;
- статус `IsActive`;
- audit-палі;
- `RowVersion`.

Правілы:

- `Id/Key` ствараецца backend-ам і не паказваецца ў форме;
- код змяшчае роўна 4 знакі;
- код нармалізуецца ў верхні рэгістр;
- код унікальны ў межах усёй табліцы `Departments`;
- нельга прызначыць падраздзяленне бацькам самому сабе;
- нельга стварыць цыкл у іерархіі;
- бацькоўскае падраздзяленне павінна быць актыўным;
- нельга дэактываваць падраздзяленне з актыўнымі даччынымі падраздзяленнямі або месцамі захоўвання;
- фізічнае выдаленне не выкарыстоўваецца.

Endpoints:

```text
GET    /api/departments
GET    /api/departments/options
GET    /api/departments/{id}
POST   /api/departments
PUT    /api/departments/{id}
POST   /api/departments/{id}/activate
POST   /api/departments/{id}/deactivate
```

## 5. Месцы захоўвання

Рэалізаваны іерархічны даведнік `StorageLocation`.

Палі:

- аўтаматычны ўнутраны `Id` тыпу GUID;
- бізнес-код і назва;
- падраздзяленне-ўладальнік;
- адзін абавязковы характар месца;
- мінімум адзін тып выкарыстання;
- бацькоўскае месца захоўвання;
- апісанне;
- статус, audit-палі і `RowVersion`.

Характары месца:

- `Premises` — памяшканне;
- `Territory` — тэрыторыя;
- `Container` — ёмістасць;
- `Zone` — зона;
- `Other` — іншае.

Тыпы выкарыстання:

- `Warehouse` — склад;
- `Production` — вытворчае захоўванне;
- `QualityHold` — каранцін якасці;
- `Waste` — захоўванне адходаў;
- `Other` — іншае.

Адно месца можа мець некалькі тыпаў праз табліцу `StorageLocationTypeAssignments`, але не можа быць захавана без тыпу.

Правілы кода:

- `Id/Key` генеруецца аўтаматычна і недаступны ў UI;
- код змяшчае роўна 4 знакі;
- код нармалізуецца ў верхні рэгістр;
- код унікальны ў межах усёй табліцы `StorageLocations`.

Іерархія абароненая ад self-reference і цыклаў. Месца з актыўнымі даччынымі месцамі нельга дэактываваць.

Endpoints:

```text
GET    /api/storage-locations
GET    /api/storage-locations/options
GET    /api/storage-locations/kinds
GET    /api/storage-locations/types
GET    /api/storage-locations/{id}
POST   /api/storage-locations
PUT    /api/storage-locations/{id}
POST   /api/storage-locations/{id}/activate
POST   /api/storage-locations/{id}/deactivate
```

## 8. Праверкі

Лакальна правераны:

- зборка ўсяго .NET solution без errors і warnings;
- Angular production build;
- Angular lint;
- прымяненне EF Core migrations;
- `/health/ready`;
- загрузка Angular і асноўных API даведнікаў.

Integration tests пакрываюць Identity, authorization, refresh-token rotation, стварэнне падраздзялення і месца з некалькімі тыпамі, абавязковасць мінімум аднаго тыпу і default-налады карыстальніка. Поўны запуск Testcontainers выконваецца ў CI, таму што лакальная Windows-машына не мае Docker.

## 9. Адзінкі вымярэння

- міжнародны JSON-каталог з 249 адзінкамі для выбару;
- капіраванне кода, англійскай назвы, сімвала і літарнага кода ў SQL Server;
- лакальныя назвы без дадання новых моўных слупкоў;
- тыпы велічынь, дакладнасць і актыўнасць;
- прамыя і зваротныя пералікі з каэфіцыентам і зрушэннем;
- Angular-дыялогі выбару адзінкі і стварэння пераліку.
- дынамічнае тлумачэнне суадносін адзінак пры навядзенні на радок пераліку.

Падрабязнае рашэнне: [units-of-measure.md](units-of-measure.md).

## 10. Абсталяванне

- даведнік без штучнага бізнес-кода і без дублявання месца захоўвання;
- неабавязковы ўнікальны інвентарны нумар;
- іерархія ліній, машын і вузлоў;
- неабавязковыя тыпы, якія ствараюцца карыстальнікам без пачатковага seed;
- храналагічныя падзеі эксплуатацыйных станаў;
- будучыя падзеі для плана рамонтаў і абслугоўвання без заўчаснай змены бягучага стану;
- рэдагаванне інтэрвалаў стану і неабавязковая дата завяршэння пры стварэнні;
- Angular-дыялогі рэдагавання, тыпаў і змены стану.

Падрабязнае рашэнне: [equipment.md](equipment.md).

## 11. Арганізацыя і агульныя адрасы

У сістэме захоўваецца роўна адна арганізацыя з фіксаваным ключом `1`. Для яе рэалізаваная непасрэдная форма рэдагавання без спіса арганізацый і пераключэння паміж імі.

Профіль змяшчае юрыдычную і гандлёвую назвы, прававую форму, ISO-код краіны, падатковы, статыстычны і рэгістрацыйны нумары, валюту, часавы пояс, мову, кантакты і ніжні калантытул друку. Гісторыя профілю не захоўваецца; выкарыстоўваюцца audit-палі і `RowVersion`.

Адрасы вынесены ў агульную табліцу `Addresses`. Адрас належыць роўна аднаму ўладальніку: арганізацыі, падраздзяленню або месцу захоўвання. Захоўваюцца тып, краіна, населены пункт, паштовы індэкс, свабодны радок адраса, GLN, прыкметы асноўнага і актыўнага адраса. GLN правяраецца па фармаце і кантрольнай лічбе і ўнікальны ў сістэме.

Старое поле `StorageLocations.Address` выдалена. Migration перанесла яго запоўненыя значэнні ў асноўныя адрасы тыпу `Delivery` перад выдаленнем слупка.

Дададзены permissions `Organization.View` і `Organization.Manage`, API арганізацыі і адрасоў, старонка `/administration/organization` і паўторна выкарыстаны Angular-рэдактар адрасоў для арганізацыі, падраздзяленняў і месцаў захоўвання.

Падрабязнае рашэнне: [organization.md](organization.md).

## 12. Catalog items

Рэалізаваны агульны даведнік `CatalogItem` без штучнага бізнес-кода. Ён змяшчае працоўную і поўную назвы, неабавязковы артыкул, жорсткі тып, абавязковую базавую адзінку вымярэння, апісанне, статус і тэхнічныя audit/concurrency палі.

Запоўнены артыкул унікальны ў межах тыпу элемента. Усе тыпы захоўваюцца ў адной табліцы, але ў асноўным меню адкрываюцца як асобныя старонкі: прадукцыя, праца, асноўныя і дапаможныя матэрыялы, паўфабрыкаты, тара і ўпакоўка, аснастка і інструменты, запчасткі, набываемыя паслугі і адходы.

Падрабязнае рашэнне: [catalog-items.md](catalog-items.md).

## 13. Што яшчэ не зроблена ў Release 1

Зыходны roadmap змяшчае наступныя даведнікі і функцыі, якія яшчэ не рэалізаваныя:

- прычыны і катэгорыі прастояў;
- нарматывы прадукцыйнасці з гісторыяй дзеяння.
