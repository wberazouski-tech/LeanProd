# Графікі працы і вытворчыя календары

## Мадэль

`WorkSchedule` апісвае паўтаральны графік працы, а не расклад канкрэтнага супрацоўніка. `Main` — асноўны графік арганізацыі, `Optional` — дадатковы графік для асобных падраздзяленняў. Дапускаецца толькі адзін актыўны `Main`: гэта правяраюць сэрвіс і ўнікальны фільтраваны індэкс SQL Server.

Станы графіка: `Draft`, `Active`, `Archived`. Пры разліку выкарыстоўваюцца толькі актыўныя графікі. Непасрэдна прызначыць падраздзяленню можна толькі актыўны `Optional`, а само падраздзяленне таксама павінна быць актыўным. Асноўны графік успадкоўваецца без прамога прызначэння.

Цыкл можа быць штодзённым (`Daily`, 1 дзень), тыднёвым (`Weekly`, 7 дзён) або адвольным (`Custom`, ад 1 да 366 дзён). Нумар дня цыкла разлічваецца адносна `CycleAnchorDate`.

`WorkScheduleDay` задае звычайны дзень цыкла (`Workday`) або спецыяльны шаблон: `PreHoliday`, `Holiday`, `Saturday`, `Sunday`. Звычайныя дні маюць нумары ад 1 да даўжыні цыкла, спецыяльныя шаблоны — нумар 0. Для кожнага ўключанага спецыяльнага шаблону павінен існаваць адпаведны запіс.

Інтэрвалы дня спасылаюцца на змены `WorkShift` і захоўваюць час пачатку, час заканчэння, парадкавы нумар і прыкмету пераходу праз поўнач `CrossesMidnight`. Сэрвіс разлічвае працягласць у хвілінах у `PaidMinutes`. Працягласць павінна быць дадатнай; актыўныя інтэрвалы правяраюцца на перакрыццё ў межах шаблону дня. Пры захаванні ўсе інтэрвалы павінны спасылацца на актыўныя змены. Змену, якую выкарыстоўвае актыўны інтэрвал, нельга дэактываваць.

Уключаны шаблон без інтэрвалаў азначае непрацоўны дзень і не замяняецца звычайным працоўным днём. Начны інтэрвал належыць дню свайго пачатку; пусты шаблон наступнага дня не дадае новых інтэрвалаў. Гл. [рашэнне пра пустыя шаблоны](decisions/scheduling-empty-day-templates.md).

`ProductionCalendar` захоўвае выключэнні для канкрэтных дат: святы, перадсвяточныя дні, перанесеныя і спецыяльныя працоўныя або непрацоўныя дні. Для адной даты ў календары дапускаецца адно выключэнне. Пры разліку выкарыстоўваецца толькі актыўны асноўны каляндар; такіх календароў можа быць не больш за адзін. Субота і нядзеля вызначаюцца праз `DateOnly.DayOfWeek`, таму асобныя запісы для кожнага выхаднога не патрабуюцца.

## Выбар графіка і шаблону дня

1. Калі ў падраздзялення зададзены актыўны графік праз `Department.WorkScheduleId`, выкарыстоўваецца ён. Калі падраздзяленне з указаным ідэнтыфікатарам не існуе, вяртаецца памылка адсутнасці запісу.
2. Калі актыўнага прызначанага графіка няма або падраздзяленне не ўказана, выкарыстоўваецца актыўны `Main`. Калі яго таксама няма, вяртаецца памылка адсутнасці актыўнага графіка.
3. Выключэнне асноўнага календара тыпу `Holiday`, `TransferredDayOff` або `SpecialDayOff` выбірае шаблон `Holiday`, калі ён уключаны. Выключэнне `PreHoliday` выбірае ўключаны шаблон `PreHoliday`.
4. Калі гэтыя правілы не спрацавалі, для суботы або нядзелі выбіраецца адпаведны ўключаны шаблон; у астатніх выпадках — звычайны дзень цыкла.
5. Калі абранага спецыяльнага шаблону няма, выкарыстоўваецца звычайны дзень цыкла. Калі і ён адсутнічае, вынік змяшчае пусты спіс інтэрвалаў. Існуючы пусты спецыяльны шаблон захоўвае свой прыярытэт.

У бягучай рэалізацыі `TransferredWorkingDay` і `SpecialWorkingDay` не адмяняюць уключаныя шаблоны суботы і нядзелі. Поле `TransferredFromDate` захоўваецца як звестка пра перанос, але не выкарыстоўваецца для капіявання інтэрвалаў з іншай даты.

## API і доступ

| Аперацыя | Маршрут |
| --- | --- |
| Спіс графікаў | `GET api/work-schedules` |
| Дэталі графіка | `GET api/work-schedules/{id}` |
| Стварэнне і абнаўленне графіка | `POST api/work-schedules`, `PUT api/work-schedules/{id}` |
| Прызначэнне і зняцце прызначэння падраздзялення | `POST` і `DELETE api/work-schedules/{id}/departments/{departmentId}` |
| Разлік дня | `GET api/work-schedules/effective?departmentId=&date=YYYY-MM-DD` |
| Спіс і стварэнне змен | `GET` і `POST api/work-shifts` |
| Абнаўленне змены | `PUT api/work-shifts/{id}` |
| Спіс і стварэнне календароў | `GET` і `POST api/production-calendars` |
| Абнаўленне календара | `PUT api/production-calendars/{id}` |

Для прагляду патрэбны дазвол `WorkSchedules.View`, для змяненняў — таксама `WorkSchedules.Manage`. Правы правяраюцца на серверы. `SystemAdministrator` і `MasterDataAdministrator` маюць абодва дазволы; астатнія ролі з бягучай матрыцы маюць толькі прагляд графікаў.

Абнаўленне графіка, змены або календара патрабуе `RowVersion` у фармаце Base64. Канфлікт версій вяртаецца як канфлікт змяненняў. Абнаўленне графіка замяняе яго шаблоны і інтэрвалы перададзеным наборам; абнаўленне календара замяняе набор выключэнняў дат.

Інтэрфейс даступны па маршруце `/administration/work-schedules` і змяшчае графікі, змены і вытворчыя календары. Магчымасць рэдагавання залежыць ад дазволу `WorkSchedules.Manage`.
